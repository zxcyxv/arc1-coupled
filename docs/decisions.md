# ARC-AGI-1/2 본 학습: 결정 사항 (2026-10-25)

TRM(SamsungSAILMontreal/TinyRecursiveModels, 커밋 `c011037`)과 공정하게 비교하는 coupled 모델 본 학습의 설정이다.
TRM 쪽 사실은 TRM 원본 코드(`pretrain.py`, `puzzle_dataset.py`, `models/losses.py`, `evaluators/arc.py`,
`dataset/build_arc_dataset.py`)에서 확인했다.

## 1. 확정

| 항목 | 결정 |
|---|---|
| 모델 | coupled: bands 지각 + 과제별 lasso 규칙 헤드 Θ + **Γ(틀 색) 항**(frames 8). Γ는 10-25 ≤10 절제 결과로 채택했다(아래 표) |
| 데이터 | ARC-AGI-1 TRM 분할. training 400 + evaluation 400 + ConceptARC 160 = 960과제. 학습 쌍 3,988(training/concept는 test 쌍까지, evaluation은 시범만). 시험은 evaluation test 쌍 419 |
| 증강 | TRM/URM 빌더와 동일(seed 42). 과제마다 원본 + 1000판(D4 8종 × 색 1~9 순열, 검정 고정, 해시로 중복 제거). 평행이동은 (판, 예시)마다 데이터를 만들 때 고정하고, 판마다 한 예시는 평행이동 없음. 시험 쌍은 평행이동 없음. 판 1001개를 못 채운 과제가 164개라 판은 모두 876,405개이고, 시험 보기는 385,815개다. TRM 원본 배열과 바이트 단위로 같음을 확인했다(README) |
| 캔버스 | 30×30(TRM과 동일). EOS는 자리가 있을 때만 두고, 오른쪽 아래 모서리는 pad. 레인 = 입력 캔버스 + 출력 캔버스 = 1,800토큰 |
| 시범 | 학습과 평가 모두 전부 사용(상한 없음). 학습 비용은 레인 수로만 정해지고, 평가 레인은 +1.2% |
| TRM과 같은 최적화 | AdamATan2 β (0.9, 0.95), lr 1e-4(워밍업 2,000스텝 후 상수), weight decay 0.1(모든 파라미터), 글로벌 배치 768, EMA 0.999(평가와 저장에 사용). AdamATan2는 TRM이 쓰는 `adam-atan2==0.0.3` 커널 식 그대로다: `p -= (lr/bc1)·atan2(m, √v/√bc2)`. 이전 구현은 `lr·atan2(m/bc1, √(v/bc2))`라 초기 약 50스텝에서만 달랐다 |

| loops | 16. 그룹마다 16세그먼트를 돈 뒤 교체 |
| ACT | 사용 안 함. q_halt 헤드도 없음 |
| 세그먼트 | 8블록, **마지막 4블록만 역전파**. carry는 세그먼트 경계에서 detach. TRM은 30층 패스 중 10을 역전파한다. 10-25에 시간 때문에 2로 줄였다가 ≤10 절제를 보고 4로 되돌렸다. ≤10에서 32블록 역전파 2는 최종 54/278(칸 0.857), 역전파 4는 69/278(칸 0.868)이었다. 블록 8개 역전파 4는 6k에 50/278(칸 0.853)로, 같은 스텝의 32블록 역전파 4(50, 칸 0.855)와 같았다. 즉 손해는 블록 수가 아니라 역전파 수에서 온다. 대가로 스텝당 비용이 2블록보다 약 33% 크다. 설명과 전체 표는 [blocks_and_backprop.md](blocks_and_backprop.md)에 있다 |
| 학습 길이 | **50k 에폭**(TRM의 절반). 사용자가 멈추라고 하면 그 전에 멈춘다(`run.sh stop` 후 `run.sh eval`) |
| 벤치마크 | ARC-AGI-1(`configs/arc1.json`)과 ARC-AGI-2(`configs/arc2.json`). ARC-2는 TRM 분할(training2 1000 + evaluation2 120 + ConceptARC 160 = 1,280과제, 에폭당 학습 쌍 5,573, 시험은 evaluation2 test 쌍 172). TRM README도 ARC-2를 같은 레시피로 돌렸다 |
| 레인 교체 | 동시 교체(16스텝마다 모든 레인). 스도쿠 런과 같은 방식 |
| 손실 | TRM의 lm 손실. 레인마다 라벨 칸(격자 + EOS) 평균 stablemax CE(FP64), 레인 합 ÷ 768. 기울기 all-reduce는 SUM |
| grad clip | 없음. 손실이나 기울기가 유한하지 않으면 마지막 체크포인트를 남기고 멈춤 |
| 학습 중 평가 | 5천 에폭마다(10-25에 1만에서 줄임: 50k 에폭에서 10점): 8판(원본 + 고정 7판) 투표를 (득표, 시범 정합도) 순으로 정렬해 pass@1/pass@2. 원본 판 exact도 기록(TRM `all/exact_accuracy`와 비교용) |
| 최종 평가 | 1001판 투표로 pass@1, 2, 5, 10, 100, 1000. 동률은 시범 정합도로 깸. 과제 가중(TRM과 동일: 과제마다 test 쌍 정답 비율, 400과제 평균) |
| 하드웨어 | **4×H100 SXM**, on-demand, DDP(10-25에 PRO 6000 S에서 바꿈: 대역폭 약 2배로 기간 절반, 비용은 비슷). `scripts/run.sh` 하나로 실행하고 모니터링. Max CUDA 12.4 호스트면 torch 2.11+cu126(TRM이 고정한 것과 같은 CUDA 12.6) |

### 평가 세 종류

| 평가 | 판 수 | 언제 | 1회 비용(4×H100 SXM, 추정) | 무엇을 보나 |

| quick | 1(원본) | 1천 에폭마다 | 약 15초 | 원본 판 exact(쌍 가중, 과제 가중). 모니터링용 |

- 결과는 `runs/<런>/eval.jsonl`에 `kind`(quick/vote/final)로 쌓인다.

### 체크포인트

| 종류 | 내용 | 크기 | 언제, 몇 개 | 용도 |
|---|---|---:|---|---|
| 전체 `runs/<런>/step_N.pt` | 가중치, EMA, 옵티마이저, 스텝, 데이터 커서 | 약 60 MB | 2,048스텝마다와 정지 때, 최근 2개 | 재개(같은 `--out`으로 다시 시작) |
| milestone `runs/<런>/milestones/step_N.pt` | EMA 가중치와 설정 | 약 15 MB | vote 평가 때마다(5천 에폭)와 학습 끝 | 학습 뒤 아무 시점이나 1001판 평가 |

- `run.sh archive`는 로그와 평가를 `docs/evidence/run_<런>/`으로, milestone을 `checkpoints/run_<런>/`으로 복사한다. 런당 약 10 × 15 MB다. 그 뒤 `git add -f`로 커밋하고 푸시한다(`*.pt`는 gitignore 대상).
- 학습 뒤 milestone을 평가하려면: `CKPT=checkpoints/run_arc1/step_N.pt bash scripts/run.sh eval`(또는 `runs/arc1/milestones/step_N.pt`). 결과 json과 제출 파일은 체크포인트 옆에 생긴다.
- 다른 인스턴스에서 재개해야 할 수도 있으면 최신 전체 체크포인트(60 MB)도 `git add -f`로 올린다. GitHub 파일 한도 100 MB 안이다.

## 2. 기본값 (따로 정하지 않으면 이대로)

- 1천 에폭마다 원본 판만 보는 확인을 한다(약 25초). 모니터링용이다.
- 시범 정합도: 판마다 시범 레인(자기를 뺀 Θ로 예측)을 정확히 맞힌 비율. 같으면 시범 라벨 칸의 평균 로그확률로 가른다.
- 에폭 표기 = 스텝 × 768 ÷ 3,988(TRM 명목 에폭). TRM과 비교하는 축은 스텝이다.
- 데이터 흐름: 교체 시점에만 새 그룹을 뽑는다(버리는 데이터 없음). 에폭마다 960과제를 섞어 한 번씩 방문하고, 방문마다 판 하나를 골라 그 판의 학습 쌍 전부를 한 그룹으로 넣는다. 마이크로배치 끝에서 들어가지 않는 그룹은 잘라 넣는다(TRM은 배치 끝에서 같은 식으로 자른다).
- 평가 때 시범은 학습 분할에 저장된 같은 판의 예시를 쓴다(평행이동 포함, TRM 임베딩이 본 그대로).
- 정밀도: 흔적, W, 읽기의 계산은 FP32이고 흔적의 저장만 BF16이다(아래). 사영과 FFN은 BF16 autocast. TF32는 끈다.
- Γ 틀의 softmax 읽기와 그 q/k 사영은 BF16 flash attention으로 한다(`frame_bf16`). FP32보다 10.6% 빠르고(5090에서 0.453 → 0.405 s/step), κ 차이는 최대 1.3e-2, 평균 1e-4다. ≤10 절제는 FP32로 했다.
- 흔적 갱신은 Triton 융합 커널로 한다(`fused_bands`, `arc/bands_kernel.py`, 10-25 밤). 수식과 FP32 산술은 그대로이고 메모리 트래픽만 줄인다: 블록마다 흔적을 한 번 읽고 한 번 쓰면서 k_mix, v_mix까지 내고, 역전파는 갱신이 선형이라 이전 흔적과 입력만으로 기울기를 쓴다(따로 저장하는 값 없음, 파라미터 기울기는 타일별 부분합이라 결정적).
  - 속도(5090, 64레인, 역전파 4): 398.2 → 330.0 ms/step(−17%). 커널 두 개가 스텝당 78 ms로 대역폭 하한(약 74 ms)에 가깝다. 피크 메모리는 20.1 → 22.1 GiB(32레인 마이크로배치).
  - 대조: 실제 크기에서 커널의 FP64 기준 오차는 출력과 기울기 모두 0.8~1.5e-7로 PyTorch FP32 경로(0.9~1.7e-7)와 같다. 모델(FP32, amp 끔)에서 PyTorch 경로와의 차이는 로짓 5e-6, 기울기 중앙값 4e-6. 학습 설정(amp, 컴파일)의 차이 1.5e-2는 같은 수식을 컴파일만 바꿀 때의 차이(1.7e-2)와 같다. 학습된 가중치(`runs/arc1_5090_g2` 11,328스텝)로 16세그먼트를 돌린 로짓의 FP64 기준 오차도 학습 경로와 같다(1.45e-2 대 1.43e-2). `tests/test_model.py`의 GPU 테스트가 PyTorch 경로와 대조한다.
- 흔적은 블록 사이에 BF16으로 저장한다(`trace_dtype: bfloat16`, 10-25 사용자 결정). 갱신과 기울기의 산술은 FP32다. 수식 동일이 아니고 ≤10 절제(FP32 흔적) 밖이지만, 측정에서 출력이 FP32 흔적과 구별되지 않아 11%를 택했다. 측정은 학습된 가중치(`runs/arc1_5090_g2` 11,328스텝), 8레인, 16세그먼트, FP64 기준이다.
  - 속도: 330.0 → 294.5 ms/step(−11%, 커널 전 대비 −26%), 피크 22.1 → 15.0 GiB.
  - 출력: 로짓 오차 1.52e-2(FP32 흔적 1.43e-2). FP64와 예측이 다른 칸은 약 860칸 중 5칸(FP32 흔적 6칸).
  - 차이는 가장 느린 대역(학습된 |z| 0.978)의 흔적에서만 보인다: 0.6% → 2.3%. 블록마다 생기는 반올림(최대 0.39%)을 이 대역이 약 45블록 들고 있어 약 1/√(1−|z|²) ≈ 4.8배로 쌓인다. 빠른 대역(|z| 0.64)은 차이가 없다.
  - 기울기도 BF16이 된다(autograd는 텐서의 기울기를 그 텐서의 dtype으로 둔다). 반올림 오차는 1.7e-3이다.
  - FP16은 쓸 수 없다. 순방향은 FP32와 구별되지 않지만(느린 대역 0.5%, 흔적 최대값 약 114), 흔적 기울기(손실 ÷ 768에서 중앙값 1e-10~1e-9)가 FP16에서 78~100% 0이 된다.
- `grad_accum 2`(GPU당 192레인 = 96 × 2). seed 0, 런 하나.

**Γ 채택 근거:** 조건은 "≤10에서 cmap 수준의 곡선이 나오면 채택, 아니면 coupled 그대로"였다. 10-25 절제(arc1_ctx10_trans, 278쌍, 15k스텝, 다른 설정은 10-23 coupled 런과 동일)에서 조건을 넘었다.

## 3. 미정

1. **중단 시점:** 사용자가 멈추라고 하면 멈춘다.
2. **논문 쪽:** 비교할 TRM 수치(논문 44.6% pass@2, 재현 약 40%, ARC-2 7.8%)와 추가 분석(인수인계서 §6의 후보 중에서 고름).

## 4. 확인할 것

- 첫 수십 스텝을 실측해 기간을 확정한다(`run.sh bench`).
  - 5090 실측(Γ 포함, BF16 틀, 융합 흔적 커널, BF16 흔적 저장): 역전파 4블록이면 레인당 4.60 ms(FP32 흔적 5.16 ms, 커널 전 6.22~6.33 ms).
  - 4×H100 SXM 예측(커널 전 예측 0.65 s/step에 5090 비율 0.74를 곱함, ±30%): 약 0.48 s/step. ARC-1 약 1.4일, ARC-2 약 2.0일(평가 제외).
  - 메모리: GPU당 192레인이면 grad_accum 2로 약 45 GiB(H100 80 GB 안). grad_accum 1(약 90 GiB)은 넘친다.
- (확인 완료) `adam-atan2==0.0.3`의 식을 소스에서 확인했고, 우리 구현을 같은 식으로 바꿨다(`tests/test_train.py`가 원소별로 대조).

## 5. 근거 메모

- **TRM 평가:** 학습 중 1만 에폭마다 10번 평가하고, 매번 시험 전체(419쌍 × 약 1001판, 16스텝)를 돈다. 평가기는 `aggregated_voting=True`라 예측을 지우지 않고 누적해 투표한다. 그래서 최종 수치는 체크포인트 10개의 앙상블이다. 평가 비용은 학습의 약 10%로 추정된다.
- **우리 평가 비용:** 시범 레인까지 돌려서 판마다 1,782레인(ARC-2는 530)이다. 1001판 투표 1회가 4×H100 SXM에서 ARC-1 약 3시간, ARC-2 약 1시간이라 최종 1회만 한다.
- **ACT를 끄는 근거:** ARC Prize의 HRM 분석에서 고정 16루프와 ACT의 차이가 몇 %p 이내였고, ACT의 이득은 주로 연산 절약이었다. 우리는 스텝당 연산이 같으니, 대가는 데이터 처리량(16스텝당 1번 교체)에 있다.
- **동시 교체:** 스도쿠 B-EMA 런도 모든 레인이 같은 박자로 돌았고(세그먼트별 손실 0.73 → 0.18의 톱니), 학습은 정상이었다(83.1% / 1,090).
- **색 증강을 유지하는 이유:** coupled는 색 순열 등변이 아니다(색별 토큰 임베딩과 분류기). 결합 구조를 설계한 대화에서도 "정확한 색 등변이 없으니 bands처럼 색 증강으로 근사한다"고 정했다.
